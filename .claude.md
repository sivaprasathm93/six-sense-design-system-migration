# Claude guidance

## Project context

This repository is a design-system migration exercise for
`apps/web-dashboard/src`. The migration replaces legacy `@old/ui` Buttons with
`@acme/ds` Buttons and maps eligible hard-coded hex colors to tokens from
`tokens/primitive-tokens.json`. Card and Modal are intentionally out of scope.

Read `README.md` for usage, commands, and output locations;
`knowledgeBase/designSystemsMigration.md` for implementation details; and
`report/REPORT.md` for the current migration counts and unresolved values. If the
candidate brief is provided separately, treat it as the source of exercise
requirements.

## Editing rules

- Keep application changes under `apps/web-dashboard/src` unless the task
  explicitly requires another location.
- Do not edit `stubs/` or `tokens/`; the token file is authoritative input to
  the codemod.
- Put migration tooling and fixtures under `codemods/`.
- Prefer syntax-aware, small edits. Preserve comments, quote style, and
  unrelated legacy components.
- Never guess a token for an unmatched color or a mapping for an unknown
  dynamic Button value. Leave it unchanged and add/update the report or an
  explicitly scoped exception.
- `TODO(ds-migration)` comments are generated from the report's review items.
  Delete one only by resolving its item; do not hand-write new ones.
- `apps/web-dashboard/src/styles/tokens.generated.css` is generated from
  `tokens/primitive-tokens.json`, by `npm run migrate` as part of a migration
  run or by `npm run tokens:css` on its own. Never hand-edit it; change the
  token file and regenerate, or `npm run tokens:check` fails.
- `knowledgeBase/codemod-interview-guide.md` is local interview preparation
  and intentionally ignored by Git; do not force-add it.

## Migration workflow

1. Run `npm run typecheck` before source changes.
2. Run `npm run migrate:dry-run` and inspect the proposed edits and review
   items before applying the migration.
3. Use `npm run migrate` only after reviewing the preview. Check the generated
   `report/REPORT.md` and resolve or document every flagged item.
4. Run `npm run check` after changes. It runs fixture tests, the token-layer
   drift check, color lint, and typecheck; all must pass.

The migration command defaults to dry-run. A second write run should make no
source changes. The color exception list must remain narrow and capped by
file, value, context, and occurrence count.
